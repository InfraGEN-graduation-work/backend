# 입력 검증 정책

노드 속성 입력에 적용하는 검증 규칙과 그 이유를 기록한다. 검증은 컴포넌트별 `ComponentParser`와 `ParsingService`가 생성 요청의 파싱 단계에서 수행한다. 환경변수 금지 문자는 프로젝트 저장 경로에서 검사하지 않는다.

## 포트

- 포트를 입력받는 컴포넌트(애플리케이션과 DB, 캐시)는 1024 이상 65535 이하여야 한다(`PARSING400_5`). NGINX는 외부 공개 포트를 입력받아 1 이상 65535 이하를 허용하고 어기면 `PARSING400_36`이다.
- 그래프 안에서 포트가 겹치면 `PARSING400_4`로 거부한다.
- 포트를 입력받지 않는 컴포넌트(Caddy)는 파서의 `requiresPort()`가 false라서 이 검사를 거치지 않는다.

## 필수값과 형식

- 이미지 버전은 DB, 캐시, 웹 서버에서 필수다. 값이 없으면 타입별 에러 코드로 거부한다.
- 데이터베이스 이름은 영문, 숫자, 언더바만 허용한다(`PARSING400_6`). DB 비밀번호는 8자 이상이어야 한다(`PARSING400_7`). 사용자 이름과 비밀번호의 누락은 타입별 에러 코드다.
- 애플리케이션은 서비스 이름과 런타임 버전이 필수이고 Spring Boot의 Java 버전과 Node.js 버전은 숫자만 허용한다(`PARSING400_21`, `PARSING400_32`). 버전 값이 Dockerfile의 `FROM` 줄에 그대로 들어가므로 형식을 제한해 설정이 바뀌지 않게 한다.
- 웹 서버(Caddy)의 이미지 버전, 도메인, 볼륨 규칙은 [caddy-web-server-policy.md](caddy-web-server-policy.md)를 따른다.

## 환경변수 금지 문자

- DB와 Redis 노드의 사용자 이름과 비밀번호에 큰따옴표, 백슬래시, 달러 기호, 줄바꿈, NUL이 있으면 `PARSING400_33`으로 거부한다. 값과 필드 이름은 응답에 노출하지 않는다.
- 이스케이프하지 않고 거부하는 이유는 이스케이프 규칙이 Docker Compose 전용이라 Node.js가 같은 값을 다르게 읽기 때문이다.
- 생성 단계에도 같은 문자 집합을 검사하는 마지막 방어선이 있다. 줄바꿈과 NUL은 `GENERATION400_13`, 큰따옴표와 백슬래시와 달러 기호는 `GENERATION400_14`로 거부한다. 이 검사는 LOCAL `.env` 생성에서만 쓰이고 CLOUD Compose의 `${...}` 참조는 거치지 않는다.

## 사용자 입력이 생성 파일에 직접 들어가는 곳

- 숫자 버전은 형식을 검증한다. 도메인은 호스트명 형식만 허용한다.
- 데이터베이스, 캐시, Caddy의 이미지 버전과 볼륨 이름은 앞뒤 공백을 제거한 뒤 `ComposeYamlValueValidator`로 형식을 검사하고, 위반하면 타입별 에러 코드로 거부한다. 두 값이 Compose YAML의 `image:` 줄, 볼륨 마운트 줄, 루트 `volumes:` 키에 그대로 들어가므로 줄바꿈, 공백, `${...}`, 콜론으로 구조가 바뀌는 것을 막는다. 인코딩이 아니라 거부하는 이유는 환경변수 값과 같다.
  - 이미지 버전은 Docker 이미지 참조 형식(`이름[:태그][@다이제스트]`)이어야 한다. 저장소 경로는 소문자, 태그는 128자 이내, 다이제스트는 `알고리즘:16진수 32자 이상`이다. 그래서 태그가 빈 `mysql:`, 대문자가 든 `MySQL:8`, 짧은 다이제스트처럼 Docker가 거부할 값도 걸러낸다.
  - 볼륨 이름은 값이 있을 때만 `[a-zA-Z0-9][a-zA-Z0-9_.-]*`를 허용한다. 비어 있으면 볼륨 없이 생성한다(Caddy는 도메인이 있으면 필수).
  - 에러 코드: MySQL은 `PARSING400_44`(이미지), `PARSING400_45`(볼륨), Redis는 `PARSING400_46`, `PARSING400_47`, PostgreSQL은 `PARSING400_48`, `PARSING400_49`, MongoDB는 `PARSING400_50`, `PARSING400_51`, Caddy는 `PARSING400_42`, `PARSING400_43`이다.
- NGINX의 이미지 버전은 NGINX 파서가 문자 구성만 검사하므로 위 이미지 참조 검사보다 느슨하다.
