# 그래프 연결 정책

캔버스 그래프의 노드와 연결선에 적용하는 규칙과 그 이유를 기록한다. 검증은 `ValidateGraphStructure`(구조)와 `ParsingService`(포트, 컴포넌트 변환)가 생성 요청의 파싱 단계에서 수행한다. 구현 위치는 [architecture_convention.md](../harness/project_code_convention/architecture_convention.md)를 따른다.

## 노드와 연결선의 기본 조건

- 노드가 하나도 없으면 `PARSING400_1`로 거부한다. 노드와 연결선 목록에 빈 항목이 있으면 `PARSING400_28`이다.
- `nodeId`는 필수이고(`PARSING400_14`) 그래프 안에서 유일해야 한다(`PARSING400_15`). 컴포넌트 타입도 필수이며(`PARSING400_3`) 지원하는 타입이어야 한다(`PARSING400_11`).
- 연결선의 `source`와 `target`은 필수이고(`PARSING400_16`) 존재하는 노드를 가리켜야 한다(`PARSING400_8`).
- 같은 `source`와 `target`의 연결선이 중복돼도 하나로 센다. 거부하지 않는다.

## 연결 방향

- 화살표는 요청이 흐르는 방향이 아니라 먼저 뜨는 쪽에서 나중에 뜨는 쪽을 가리킨다. 연결선의 `source` 시작 우선순위가 `target`보다 높으면 `PARSING400_10`으로 거부한다.
- 시작 우선순위는 데이터베이스 1, 캐시 2, 애플리케이션 3, 웹 서버 4다. 따라서 `DB → 앱`, `Redis → 앱`, `앱 → 웹 서버`가 허용되고 `앱 → DB`, `웹 서버 → 앱`은 거부된다. 의미로는 화살표가 가리키는 쪽이 source에 의존한다.
- 같은 우선순위끼리의 연결은 방향 검사를 통과하지만, 순환이 생기면 `PARSING400_9`로 거부한다.
- 이 방향 규칙은 `ComponentType`의 우선순위만으로 결정되므로 새 컴포넌트는 우선순위를 정하는 것으로 방향이 정해진다.

## 의존 중복

- 하나의 애플리케이션에 같은 타입의 의존 컴포넌트를 둘 이상 연결하면 `PARSING400_25`로 거부한다. 같은 타입의 접속 변수가 서로 덮어써지기 때문이다. 서로 다른 타입(예: MySQL과 PostgreSQL)은 함께 연결할 수 있다.
- 하나의 DB를 여러 애플리케이션이 공유하는 것은 허용한다.
- 같은 타입의 데이터베이스 또는 캐시 노드를 그래프에 둘 이상 두면 앱 연결 여부와 상관없이 `PARSING400_29`로 거부한다. LOCAL_DEV의 `.env`는 타입별 고정 변수를 쓰므로 노드가 둘이면 마지막 값만 남고, 앱에 연결되지 않은 노드도 컨테이너와 `.env`에 등록되기 때문이다.
- 애플리케이션 노드는 타입 중복 검사 대상이 아니다. 파싱은 앱이 여럿인 그래프를 허용하고 CLOUD_DEPLOY 생성 단계에서 앱이 둘 이상이면 `GENERATION400_10`으로 거부한다.

## 웹 서버

- 웹 서버(`WEB_SERVER` 카테고리) 노드는 그래프에 하나만 둘 수 있고(`PARSING400_40`), 앱에서 오는 연결선 하나만 가져야 한다(`PARSING400_41`). 상세와 이유는 [caddy-web-server-policy.md](caddy-web-server-policy.md)를 따른다.
- NGINX는 이 카테고리 규칙에 더해 자체 연결·이름 검사(`PARSING400_34`, `PARSING400_35`)를 먼저 적용받는다. 두 검사는 통합하지 않고 공존한다. NGINX 그래프는 NGINX의 에러 코드를 먼저 받고, Caddy와 NGINX를 함께 두면 웹 서버 개수 규칙(`PARSING400_40`)으로 거부된다(`ValidateGraphStructureTest`).

## 연결되지 않은 노드의 처리

- LOCAL_DEV: 의존 인프라는 앱 연결 여부와 상관없이 Compose service로 만들고 컨테이너 실행에 필요한 변수를 `.env`에 등록한다. 앱 접속 변수는 앱에 연결된 의존에만 만든다.
- CLOUD_DEPLOY: 앱에 연결된 의존 인프라만 Compose에 포함한다. 연결되지 않은 인프라는 산출물에 들어가지 않는다.
- 검증 순서는 구조 오류(방향, 순환, 의존 중복)를 먼저 걸러낸 뒤 그래프 전체의 타입 중복과 웹 서버 규칙을 검사한다.
